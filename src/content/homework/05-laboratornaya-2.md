**Условие.** Работа про то, как ведёт себя многорукий бандит, когда мир не стоит на месте. Вам нужна
**своя сцена** — реальная или вымышленная задача выбора из нескольких альтернатив с неизвестной отдачей,
которая **медленно меняется со временем**. Сцена семинара (тимлид и три подхода к разработке) годится
как образец; своя сцена приветствуется.

Без формального описания сцены работа не принимается:

* что является **рычагом** (действием) — не меньше трёх;
* что является **вознаграждением** и как оно связано со скрытым средним μ каждого рычага;
* что именно **дрейфует** — случайное блуждание средних μ — и с какой интенсивностью σ;
* как устроен цикл взаимодействия: **спринт = один выбор + одно вознаграждение**.

**Среда.** Дельта от кода занятия: средние стартуют из заданного вектора (в образце 0,3 / 0,8 / 1,3),
каждый спринт все средние дрейфуют — μ ← clip(μ + N(0; σ), 0,1; 1,9), наблюдения 0/1/2 порождаются
из среднего кусочно-линейно (`probs_from_mean`), среда ведёт лог `mu_log[t]` — историю средних, и метрика
считается офлайн по этому логу.

**Методы — минимум для сравнения.**

* стратегии: **ε-жадная** (ε = 0,1), **UCB** (c = 2), **градиентная** (h_α = 0,1);
* обновление оценок: честное среднее (**1/n**) и постоянный шаг (**α = 0,1 и 0,3**);
* одна и та же среда, одинаковое число спринтов (1000), сравнение в одинаковых условиях.

**Три обязательных исследования.**

1. **Стратегии в движущемся мире.** При σ = 0,05 сравнить ε-жадную, UCB и градиентную (для оценок
   α = 0,1). Результат — таблица дохода и доли выборов текущего лучшего рычага, с пояснением различий.
2. **1/n против α.** Показать, где и насколько проигрывает честное среднее и как меняет картину постоянный
   шаг. Сравнивать **разброс**, а не только среднее.
3. **Влияние скорости дрейфа σ.** Три режима: медленный σ = 0,01, рабочий 0,05, бурный 0,2. Проверить
   гипотезу: чем больше σ, тем сильнее проигрывает 1/n; при σ → 0 разрыв должен исчезнуть, и честное
   среднее снова становится лучшим. Подтвердить или опровергнуть.

Исследования 4+ (свои σ, свои ε / c / h_α, четвёртая стратегия) — по желанию, за плюс. Готовая зацепка
с занятия: почему градиентная при дрейфе хуже. Две версии — инерционная базовая линия 1/t и слишком
мелкий шаг предпочтений — мы проверили, они не объясняют (54% против 53% и 56%); осталась третья:
мягкий максимум не обнуляет вероятность плохой руки.

**Требования к числам.**

* **Не меньше 100 сидов на каждую точку** таблицы: один прогон ничего не доказывает.
* В отчёт — **медиана и IQR**, плюс среднее и разброс: распределения не гауссовы, одного среднего мало.
* Для каждой точки — **диапазон сидов** (например, 0–99) и команда запуска.

**Что сдаётся** — файлом в чат: `REPORT.md` + код + чек-лист + лог.

1. **Код**: среда с дрейфом, агент (все стратегии), прогон. Чистый python3, без numpy. Чужие готовые
   куски допустимы только с обоснованием выбора.
2. **Два графика** как минимум: доход по времени (скользящее среднее) и доли выбора рычагов по времени.
3. **REPORT.md**: постановка (сцена, рычаги, вознаграждение, что дрейфует); методы и настройки; таблицы
   результатов; **выводы — минимум три, каждый с цифрой из ваших таблиц**; воспроизводимость — диапазон
   сидов и команды запуска.
4. **Чек-лист критериев** с указанием, где в отчёте лежит каждый пункт. Без него работа к приёмке
   не принимается; ссылка на несуществующий раздел = чек-лист не заполнен.
5. **`run_log.jsonl`** из прогона: одна строка на точку, обязательные поля `n_runs`, `seed_from`,
   `seed_to`, `metric`, `command`.

**Критерии.**

* постановка формализована — без неё работа не принимается;
* все три обязательных исследования, ≥ 100 сидов, медиана + IQR;
* каждый вывод подкреплён цифрой из собственных прогонов;
* код воспроизводится командой из отчёта;
* обоснование любых заимствованных кусков кода;
* лог содержит все обязательные поля, числа в отчёте совпадают с логом.
