# tournament.py: разбор кода

Скрипт короткий, но неочевидных мест в нём хватает: почему сид мира вшит в файл, почему метрики считаются по истинным средним, откуда в выводе берутся скобки. Ниже — по порядку, функция за функцией.

## Меню конфигураций

| № | Стратегия | Ручки |
|---|---|---|
| 1 | eps-greedy | eps = 0.05, alpha = 0.10 |
| 2 | UCB | c = 4, правило 1/n |
| 3 | gradient | eta = 0.05 |
| 4 | eps-greedy | eps = 0.20, правило 1/n |
| 5 | UCB | c = 1, alpha = 0.10 |
| 6 | UCB | c = 2, правило 1/n |
| 7 | greedy | без разведки |
| 8 | gradient | eta = 0.20 |
| 9 | eps-greedy | eps = 0.10, alpha = 0.30 |
| 10 | eps-greedy | eps = 0.02, правило 1/n |

Правило `1/n` — честное среднее: оценка рычага усредняется по всем его наблюдениям с самого начала.
`alpha` — постоянный шаг: старая оценка забывается, вес свежего наблюдения не падает.

## Правила честности (почему скрипт не редактируем)

- **Детерминизм.** Сид мира вшит: `WORLD_SEED_BASE + номер мира`. Один и тот же конфиг на одном и том же мире даёт одинаковые цифры на любом ноутбуке. Правка скрипта сразу видна по цифрам, не сошедшимся с соседями.
- **Общий прогон на реванше.** На мире 2 гоняем конфигурации победителя по доходу — и гоняем их все вместе. У всех одни и те же цифры, подтасовать нечем.
- **Строка результата в чат — целиком, копированием.** Перепечатанное руками число проверить нельзя.

## Мир: константы

- `ARMS = 5` — пять рычагов.
- `MU0 = [0.3, 0.7, 1.1, 1.5, 1.9]` — стартовые средние отдачи рычагов.
- `LO, HI = 0.1, 1.9` — границы, в которых средние живут (клип, а не отражение).
- `WORLD_SIGMA = 0.05` — размах шага дрейфа, одинаковый во всех мирах.
- `WORLD_SEED_BASE = 777` — сид мира: `777 + N`. Поэтому миры 1, 2, 3 — три разные реализации одного и того же дрейфа.
- `STEPS = 1000` — спринтов в одном прогоне.
- `AGENT_SEEDS = 30` — сидов агента на пару «конфиг × мир».
- `REWARD_SIGMA = 0.3` — шум награды вокруг текущего среднего рычага.
- `AGENT_SEED_BASE = 50_000` — база сидов агента: `50 000 + мир·10 000 + конфиг·100 + i`. У каждого конфига и мира свой набор из 30 сидов, пересечений нет.

## `world_drift(world)`

Один путь дрейфа на мир: массив `1000 × 5` приращений к средним. Считается из сида мира и **не зависит от конфигурации** — это и есть «тот же мир, то же число спринтов» из тезиса о честном сравнении.

## `run_episode(cfg_id, drift, agent_seed)` — один прогон

1. `mu = MU0.copy()` и каждый шаг `mu = clip(mu + drift[step], LO, HI)` — средние дышат.
2. Выбор действия зависит от стратегии:
   - `greedy` — `argmax(q)`, разведки нет;
   - `eps` — с вероятностью `eps` случайный рычаг, иначе `argmax(q)`;
   - `ucb` — пока есть нетронутые рычаги, тянем их по очереди; дальше `argmax(q + c·sqrt(ln t / n))`. Бонус за неуверенность: чем меньше наблюдений у рычага, тем он привлекательнее;
   - `gradient` — вероятности выбора по softmax над предпочтениями `H` (с вычитанием максимума, чтобы `exp` не переполнялся).
3. Награда `r = normal(mu[a], 0.3)`.
4. Метрики считаются **по истинным средним `mu`, а не по наградам**: `best = mu.max()`, доля лучшего — как часто тянули рычаг с максимальным средним именно в этот момент, regret — `best − mu[a]`. Агент этих средних не видит; их знает только среда.
5. Обновление оценки:
   - `1/n` — `q[a] += (r − q[a]) / n[a]`, первое наблюдение ставит `q[a] = r`;
   - `alpha` — `q[a] += alpha·(r − q[a])`;
   - `gradient` — базовая линия `avg` (средний доход) и шаг по градиенту: `H += eta·(r − avg)·(1_a − prob)`.

## `spread(values)`

Медиана и квартили: 50-й, 25-й и 75-й процентили. Размах (минимум–максимум) не используем: у распределения с длинными хвостами он показывает крайние прогоны и почти ничего не говорит о типичном результате. Коридор — центральные 50% прогонов.

## `run_config(cfg_id, world)`

Гоняет 30 сидов агента на одном и том же пути дрейфа и собирает по трём метрикам медиану и коридор. Отсюда «доля лучшего 67% [66–68]»: медиана 67, в скобках — квартили.

## `fmt(cell, pct=False)`

Печать одной ячейки: проценты — целыми, доход и regret — с двумя знаками. Скобки в выводе — не оформление, а смысл: без них число читается как «точно столько», со скобками — как «столько, плюс-минус коридор».

## `main()`

Разбирает `--config` (1..10 или `all`) и `--world` (1, 2, 3), печатает шапку с параметрами прогона и по строке на конфигурацию, в конце — время счёта. Неверный номер конфигурации — понятная ошибка, а не трейсбек.

## Что с этим делать дома

- Гонять любые конфигурации на любом из трёх миров: `--config all --world 2`.
- Сравнивать не числа, а коридоры: перекрылись — «намёк», разошлись — «разница».
- Читать чужой вывод и проверять, что у соседа на том же конфиге и мире те же цифры: если нет — файл правили.
- Сам скрипт не редактировать: любая правка ломает и сравнение, и доверие к результату. Свои опыты — своими скриптами, скрипт турнира остаётся эталоном.
